# Hunger Trail

Daily text survival game at hungertrail.com. Hunger Games premise, Oregon Trail feel. Design and
roadmap: `docs/PLAN.md`.

## Commands

```sh
uv sync
uv run pytest                                   # all tests
uv run python -m hungertrail.game.bots          # balance report (bots play thousands of runs)
uv run uvicorn hungertrail.app:app --reload     # dev server on http://127.0.0.1:8000
```

On Windows, set `PYTHONIOENCODING=utf-8` before running scripts that print emoji.

## How it fits together

- `src/hungertrail/game/engine.py`: pure, deterministic rules. A run is `(seed, salt, setup, choices)`.
  The seed (daily, from the server secret) picks the arena; the salt (per run) rolls the dice.
- `src/hungertrail/game/cards.yaml`: all event content. The header documents the schema. Adding a
  card needs no code. `tests/test_engine.py` validates every card.
- `src/hungertrail/game/lore.py`: every franchise name, districts, traits, items, weapons.
- `src/hungertrail/runs.py`: signed run tokens. The browser holds only setup + choices; the server
  replays the run on every request. Seeds never leave the server.
- `src/hungertrail/leaderboard.py`: SQLite locally; in production a Cloudflare Worker + D1
  (`ops/leaderboard`), because Render's free disk is wiped on deploy.
- `src/hungertrail/static/`: vanilla JS front end, phone-first. `art.js` draws the pixel art.
- `src/hungertrail/beta/`: the beta game served on beta.hungertrail.com (and `/beta` locally). Its
  own engine, cards, bots and run tokens, so beta changes never touch live runs. Front end:
  `templates/beta.html`, `static/beta/`. API under `/api/beta/`. Its leaderboard is a local SQLite
  file that resets on deploy.

## Balance

Beta: `uv run python -m hungertrail.beta.bots` (add `--districts` for win rate per district).
Bots play the minigames with a skill (`SKILL` in `beta/bots.py`: smart 0.65, casual 0.4). Beta
targets: a good player (smart) about 40%, casual about 25%, random about 10-15%, hider under 5%,
and no single place much better than the smart bot. `DAMAGE`, `HIT_CAP`, `FIGHT`,
`OPPONENT_HEALTH`, `FIGHT_NEMESIS_HIT`, `OPEN_GIFT`, `SUPPLY_CAP`, `NEMESIS_FLOOR`, `NIGHT_HEAL`, `MEDICINE`
and the `DIG_*` numbers in `beta/engine.py` are the main dials (the nemesis is always the last fight if alive; card `wound`/`study` effects weaken them for it); the games' own numbers
are in `beta/minigames.py` (`FEINT_AT` sets how late a feint switches sides in the final fight). The bots'
hands react like a person's; at skill 0.55 they block about as often as the beta 4 playtest did (83% with
the feint read), so their win rates track a real player's. Beta event cards need a `place`; the header of `beta/cards.yaml`
documents the schema. An option with `minigame: hide` is played, not rolled. Every roll goes
through `_reveal`, which logs it for the wheel (`static/beta/wheel.js`). The daily script (nemesis
days and places, finale, twist, place menus) lives in `Arena`. Bump `VERSION` in `beta/runs.py`
when a change would alter runs in progress, and `RELEASE` (shown on the title screen) for each new beta.

Beta minigames are replayed: the browser sends input ticks, the server reruns the same integer
simulation. `beta/minigames.py` and `static/beta/minigames.js` must stay in step
(`test_python_and_browser_minigames_agree` runs node to compare them).

After changing odds, damage or content, run the bots. Current targets: smart bot wins about 15-20%,
random about 10%, the pure hider under 1%, about 10-16 decisions per run. `DAMAGE` in `engine.py`
is the global lethality dial.

## Deploy

- Render web service `hungertrail`, free tier, deploys automatically on push to `initial-site`
  (Blueprint: `render.yaml`). Keep `main` in step with it.
- `HT_SEED_SECRET` is generated by Render and never committed. The repo is public.
- `ops/keepalive`: Cloudflare cron Worker that pings the app every 10 minutes so it doesn't sleep.
- `ops/leaderboard`: Cloudflare Worker + D1. Deploy with `npx wrangler deploy` from that folder.
  The Worker trusts the first key that registers; the app registers on startup and `/healthz`
  reports `"leaderboard": "remote"` when it worked.
- `ops/beta`: Cloudflare Worker on beta.hungertrail.com that forwards to the Render app with
  `x-ht-site: beta`. Deploy with `npx wrangler deploy` from that folder.
- DNS for hungertrail.com is on Cloudflare (DNS only) pointing at `hungertrail.onrender.com`.
- Runs are replayed from their choices, so changing cards, odds or engine rules changes runs that
  are already in progress. Ship content and balance changes near midnight Pacific when possible.
